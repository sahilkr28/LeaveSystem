# Smart Campus Hostel DevOps - Ansible Automation

This directory contains modular Ansible configuration, clean roles, and automated playbooks to deploy and maintain the **Smart Campus Hostel & Leave Management System** across the AWS 5-node cluster, including Nagios Core monitoring and automated self-healing.

---

## 📁 Directory Structure

```
ansible/
├── ansible.cfg                    # Ansible default configuration (pipelining, inventory, roles_path)
├── inventory.ini                  # Cluster inventory (auto-generated by Terraform or default template)
├── site.yml                       # Convenience top-level site deployment playbook
├── rolling-update.yml             # Convenience top-level zero-downtime rolling update playbook
├── heal-web.yml                   # Convenience top-level self-healing playbook
├── group_vars/
│   └── all.yml                    # Global cluster variables (secrets, ports, VPC CIDR)
├── playbooks/
│   ├── site.yml                   # Full end-to-end cluster deployment across all 5 roles
│   ├── rolling-update.yml         # Zero-downtime rolling update (serial: 1) on [webservers]
│   └── heal-web.yml               # Automated self-healing recovery for unhealthy web nodes
└── roles/
    ├── common/                    # UFW rules, base packages, and Nagios NRPE monitoring agent
    ├── database/                  # PostgreSQL server, pg_hba.conf, database user & permissions
    ├── webserver/                 # Python venv, /opt/hostel-app deployment, systemd service
    ├── loadbalancer/              # HAProxy roundrobin load balancing and Stats UI (:8404)
    └── monitoring/                # Nagios Core, Apache2, PHP, host/service definitions, event handler
```

## 🏛️ Roles Overview

### 1. `roles/common`
- **Target Nodes**: `lb-01`, `web-01`, `web-02`, `db-01`
- **Responsibilities**:
  - Updates apt cache.
  - Installs base utilities, UFW firewall, and Nagios NRPE packages (`nagios-nrpe-server`, `nagios-plugins`).
  - Configures UFW policies (deny incoming, allow outgoing).
  - Permits SSH on port `22`.
  - Permits Nagios NRPE on port `5666` strictly from internal VPC (`10.0.0.0/16`).
  - Templates `/etc/nagios/nrpe.cfg` and enables `nagios-nrpe-server`.

### 2. `roles/database`
- **Target Node**: `db-01` (`[database]`)
- **Responsibilities**:
  - Installs `postgresql`, `postgresql-contrib`, and `python3-psycopg2`.
  - Configures `postgresql.conf` with `listen_addresses = '*'`.
  - Configures `pg_hba.conf` allowing connections from VPC CIDR `10.0.0.0/16` for `hostel_user` to `hostel_db`.
  - Allows port `5432` in UFW from internal VPC only.
  - Creates PostgreSQL user `hostel_user` and database `hostel_db` with full privileges.

### 3. `roles/webserver`
- **Target Nodes**: `web-01`, `web-02` (`[webservers]`)
- **Responsibilities**:
  - Installs Python 3, venv, and build prerequisites.
  - Creates application root at `/opt/hostel-app`.
  - Copies `../app/` to `/opt/hostel-app/app/`, along with root `app.py` and `requirements.txt`.
  - Sets up isolated Python virtual environment at `/opt/hostel-app/venv`.
  - Installs dependencies from `requirements.txt` into the venv.
  - Deploys `/etc/systemd/system/hostel-app.service` pointing `DATABASE_URL` dynamically to `db-01`'s private IP.
  - Allows port `5000` in UFW.
  - Enables and starts `hostel-app.service` running Gunicorn (`gunicorn -w 2 -b 0.0.0.0:5000 app:app`).
  - Probes local `/health` endpoint to verify service startup.

### 4. `roles/loadbalancer`
- **Target Node**: `lb-01` (`[loadbalancer]`)
- **Responsibilities**:
  - Installs `haproxy`.
  - Allows port `80` (HTTP) and port `8404` (Stats UI) in UFW.
  - Deploys `/etc/haproxy/haproxy.cfg` using `templates/haproxy.cfg.j2`:
    - Balances port `80` across `web-01:5000` and `web-02:5000` using `roundrobin`.
    - Configures active HTTP health checks on `/health` (`http-check expect status 200`).
    - Enables the HAProxy Stats web UI on port `8404` at `/stats`.
  - Validates and restarts `haproxy` service.

### 5. `roles/monitoring`
- **Target Node**: `ops-node` (`[ops]`)
- **Responsibilities**:
  - Installs Nagios Core (`nagios4`), Apache2, PHP, and monitoring plugins.
  - Configures Apache CGI authentication (`/etc/nagios4/htpasswd.users`).
  - Deploys host and service definitions for:
    - **HTTP 200 OK on `lb-01`**: Port 80 response check.
    - **hostel-app Port 5000 & `/health` endpoint on `web-01` & `web-02`**: HTTP check on `:5000/health`.
    - **PostgreSQL Port 5432 on `db-01`**: TCP port availability check.
    - **CPU Load and Disk Usage across all nodes**: Polled via NRPE (`check_load`, `check_disk_root`).
  - **Self-Healing Event Handler**:
    - Deploys `/usr/local/nagios/libexec/eventhandlers/restart_web.sh`.
    - Binds the event handler to `web-01` and `web-02` service checks.
    - When a service enters `CRITICAL HARD` state, triggers:
      ```bash
      ansible-playbook -i /opt/infra/ansible/inventory.ini /opt/infra/ansible/playbooks/heal-web.yml --limit <hostname>
      ```
    - Configures passwordless sudo for `nagios` user (`/etc/sudoers.d/nagios-self-heal`).

## ⚡ Self-Healing Architecture (`playbooks/heal-web.yml`)

When Nagios Core detects that a web node's `/health` endpoint has failed (`CRITICAL HARD`):
1. Nagios triggers `/usr/local/nagios/libexec/eventhandlers/restart_web.sh`.
2. The script executes `playbooks/heal-web.yml` targeting the failed node (`--limit <hostname>`).
3. The playbook:
   - Records the incident start in `/var/log/self-heal.log`.
   - Restarts `hostel-app.service`.
   - Polls `http://localhost:5000/health` until HTTP 200 is verified.
   - Appends the recovery confirmation and timestamp to `/var/log/self-heal.log`.

## 🚀 Execution Commands

```bash
cd ansible

# 1. Test node connectivity
ansible -i inventory.ini all -m ping

# 2. Run full cluster deployment (all 5 stages)
ansible-playbook -i inventory.ini playbooks/site.yml

# 3. Perform zero-downtime rolling update on webservers
ansible-playbook -i inventory.ini playbooks/rolling-update.yml

# 4. Manually trigger self-healing on a specific node (e.g. web-01)
ansible-playbook -i inventory.ini playbooks/heal-web.yml --limit web-01
```
